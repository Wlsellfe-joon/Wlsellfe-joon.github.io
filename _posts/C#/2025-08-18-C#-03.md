## Why ConcurrentQueue?

`ConcurrentQueue<T>`는 여러 스레드가 동시에 접근할 수 있는 thread-safe FIFO 컬렉션이다. `Enqueue`, `TryDequeue`, `TryPeek` 같은 공개 멤버는 동시에 호출해도 안전하다.

다만 **큐가 안전하다는 사실과 전체 작업 흐름이 안전하다는 것은 다르다.** 생산 완료 여부, 대기, 취소, 오류 전달은 별도로 설계해야 한다. 일반 `bool done`을 여러 스레드에서 읽고 쓰면 메모리 가시성 문제가 생길 수 있고, 큐가 비었을 때 `Sleep`으로 반복 확인하면 불필요한 지연과 CPU 사용이 발생한다.

## Recommended Pattern

전형적인 producer–consumer 작업에는 `ConcurrentQueue<T>`를 내부 저장소로 사용하는 `BlockingCollection<T>`이 간단하다. 생산자는 `CompleteAdding`으로 종료를 알리고 소비자는 남은 항목까지 처리한다.

```csharp
using System.Collections.Concurrent;

internal static class Program
{
    private static readonly BlockingCollection<int> WorkItems =
        new(new ConcurrentQueue<int>(), boundedCapacity: 100);

    private static void Main()
    {
        using var cancellation = new CancellationTokenSource();

        Task producer = Task.Run(() => Produce(cancellation.Token));
        Task consumer = Task.Run(() => Consume(cancellation.Token));

        try
        {
            Task.WaitAll(producer, consumer);
            Console.WriteLine("Processing complete.");
        }
        catch (AggregateException ex)
        {
            foreach (Exception error in ex.Flatten().InnerExceptions)
                Console.Error.WriteLine(error.Message);
        }
    }

    private static void Produce(CancellationToken token)
    {
        try
        {
            for (int item = 0; item < 10; item++)
            {
                token.ThrowIfCancellationRequested();
                WorkItems.Add(item, token);
                Console.WriteLine($"Enqueued {item}");
            }
        }
        finally
        {
            WorkItems.CompleteAdding();
        }
    }

    private static void Consume(CancellationToken token)
    {
        foreach (int item in WorkItems.GetConsumingEnumerable(token))
        {
            Console.WriteLine($"Dequeued {item}");
            Thread.Sleep(50); // 실제 처리 작업
        }
    }
}
```

`boundedCapacity`는 생산 속도가 소비 속도보다 빠를 때 메모리가 끝없이 증가하는 것을 막는다. 큐가 가득 차면 생산자가 대기해 자연스럽게 backpressure가 적용된다.

## Using ConcurrentQueue Directly

작업 알림이나 완료 신호가 이미 관리되는 단순한 경우에는 큐만 사용할 수 있다.

```csharp
var queue = new ConcurrentQueue<int>();
queue.Enqueue(42);

if (queue.TryDequeue(out int item))
{
    Process(item);
}
```

`IsEmpty` 확인과 `TryDequeue` 사이에는 다른 스레드가 상태를 바꿀 수 있다. “확인 후 처리”보다 `TryDequeue` 반환값을 직접 기준으로 삼는다.

## Windows Forms and UI Threads

백그라운드 스레드에서 WinForms 컨트롤을 직접 수정하면 안 된다. 결과는 UI 스레드로 전달한다.

```csharp
private void ShowResult(string message)
{
    if (InvokeRequired)
    {
        BeginInvoke(() => ShowResult(message));
        return;
    }

    resultTextBox.AppendText(message + Environment.NewLine);
}
```

긴 작업은 가능하면 직접 `Thread`를 관리하기보다 `Task`, `async/await`, `CancellationToken`을 사용한다.

## Choosing the Right Tool

- 비동기 데이터 스트림: `Channel<T>`
- 동기식 producer–consumer와 용량 제한: `BlockingCollection<T>`
- 단순한 lock-free FIFO 연산: `ConcurrentQueue<T>`
- UI 상태 공유: 큐뿐 아니라 UI thread marshal과 생명주기도 설계
