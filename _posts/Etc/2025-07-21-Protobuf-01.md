## What Protocol Buffers Are

Protocol Buffers(Protobuf)는 Google이 공개한 **schema-driven binary serialization format**이다. JSON이나 XML 문서를 압축하는 도구가 아니라 `.proto` 스키마에서 생성한 타입으로 구조화된 데이터를 바이너리 직렬화한다.

이미지 출처: [Martin Kleppmann — Schema evolution](https://martin.kleppmann.com/2012/12/05/schema-evolution-in-avro-protocol-buffers-thrift.html)

### Strengths

- 일반적인 텍스트 JSON보다 작고 파싱이 빠른 편이다.
- 여러 언어의 코드를 동일한 스키마에서 생성한다.
- 규칙을 지키면 이전/이후 버전과 호환되는 변경이 가능하다.
- 타입과 직렬화 코드가 자동 생성된다.

### Trade-offs

- 바이너리만 열어서는 사람이 읽기 어렵다.
- producer와 consumer가 스키마를 공유해야 한다.
- field number를 잘못 재사용하면 호환성이 깨진다.
- 사람이 직접 편집하는 설정에는 JSON이 더 편할 수 있다.

## Define a Schema

```protobuf
syntax = "proto3";

package example.tasks;
option csharp_namespace = "Example.Tasks";

message Task
{
  uint64 id = 1;
  string name = 2;
  repeated string labels = 3;
  optional string owner = 4;
}
```

field number는 wire format의 일부이므로 공개 후 함부로 바꾸거나 재사용하면 안 된다. 삭제한 필드는 `reserved`로 남긴다.

```protobuf
message Task
{
  reserved 2;
  reserved "legacy_name";

  uint64 id = 1;
  string name = 3;
}
```

## Compile for C#

설치 후 compiler 버전을 확인하고 C# 코드를 생성한다.

```powershell
protoc --version
protoc --proto_path=. --csharp_out=Generated task.proto
```

- `--proto_path`: import 탐색 기준 경로
- `--csharp_out`: 생성된 C# 파일의 출력 폴더
- 마지막 인자: 컴파일할 `.proto` 파일

.NET 프로젝트에서는 `Google.Protobuf`와 `Grpc.Tools` NuGet 패키지로 빌드 과정에 코드 생성을 포함할 수도 있다.

## Use the Generated Type

```csharp
using Example.Tasks;
using Google.Protobuf;

var task = new Task
{
    Id = 42,
    Name = "Schema review",
    Owner = "Yongjun"
};
task.Labels.Add("protobuf");
task.Labels.Add("csharp");

byte[] payload = task.ToByteArray();
Task restored = Task.Parser.ParseFrom(payload);
```

`repeated string labels`는 C#에서 `RepeatedField<string>`으로 생성된다. 항목은 추가할 수 있지만 generated property 자체를 다른 컬렉션으로 교체하지 않는다.

## JSON Interoperability

Protobuf 메시지를 JSON으로 표현할 때는 공식 `JsonFormatter`와 `JsonParser`를 우선한다.

```csharp
string json = JsonFormatter.Default.Format(task);
Task fromJson = JsonParser.Default.Parse<Task>(json);
```

ProtoJSON은 64-bit integer, enum, bytes 등에 별도 매핑 규칙이 있다. 양쪽에서 공식 구현을 사용하는 것이 안전하다.

## Schema Evolution Checklist

- 기존 field number의 의미나 타입을 임의로 변경하지 않는다.
- 삭제한 field number와 이름은 `reserved` 처리한다.
- 새 필드는 새 번호로 추가한다.
- enum의 0번 값은 `UNSPECIFIED` 같은 기본값으로 둔다.
- binary 호환성과 JSON 호환성을 별도로 확인한다.
- 자동 변환으로 만든 스키마는 반드시 사람이 검토한다.

JSON-to-proto 도구는 초안을 만드는 데 유용하지만 샘플 하나만으로 optionality, 숫자 범위, enum, union 성격을 정확히 추론할 수 없다.
