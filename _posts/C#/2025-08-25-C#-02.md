## What This Covers

Newtonsoft.Json(Json.NET)을 이용해 객체를 JSON으로 직렬화하고 다시 역직렬화하는 방법, 파일 저장, 오류 처리, 배포 시 주의점을 정리한다. 예시는 Windows Forms를 기준으로 하지만 JSON 처리 코드는 콘솔이나 서비스 프로젝트에서도 같다.

## Install

Visual Studio의 **프로젝트 → NuGet 패키지 관리 → 찾아보기**에서 `Newtonsoft.Json`을 설치한다.

```powershell
Install-Package Newtonsoft.Json
```

<img src="/assets/posts/CS02/01.PNG" width="800" height="150" alt="Installing Newtonsoft.Json from NuGet">

코드에서는 C++/CLI 문법인 `using namespace`가 아니라 C# 문법을 사용해야 한다.

```csharp
using Newtonsoft.Json;
```

## Serialize an Object

익명 객체도 직렬화할 수 있지만 반복해서 사용하는 데이터라면 명시적인 모델이 유지보수에 유리하다.

```csharp
public sealed class UserProfile
{
    public string Name { get; init; } = string.Empty;
    public int Level { get; init; }
}
```

Windows Forms 버튼 이벤트에서 사용자 데이터 폴더에 비동기로 저장하는 예제다.

```csharp
using Newtonsoft.Json;
using System.Text;

private async void createJsonButton_Click(object sender, EventArgs e)
{
    try
    {
        var profile = new UserProfile { Name = "HGD", Level = 3 };
        var settings = new JsonSerializerSettings
        {
            Formatting = Formatting.Indented,
            NullValueHandling = NullValueHandling.Ignore
        };

        string json = JsonConvert.SerializeObject(profile, settings);
        string directory = Path.Combine(
            Environment.GetFolderPath(Environment.SpecialFolder.LocalApplicationData),
            "WlsellfeJoon");
        string path = Path.Combine(directory, "data.json");

        Directory.CreateDirectory(directory);
        await File.WriteAllTextAsync(path, json, Encoding.UTF8);
        resultTextBox.Text = $"Saved: {path}";
    }
    catch (UnauthorizedAccessException ex)
    {
        MessageBox.Show($"파일 접근 권한이 없습니다.\n{ex.Message}", "Save failed");
    }
    catch (IOException ex)
    {
        MessageBox.Show($"파일을 저장하지 못했습니다.\n{ex.Message}", "Save failed");
    }
}
```

실행 파일 폴더는 설치 방식에 따라 쓰기 권한이 없을 수 있다. 사용자 데이터는 `LocalApplicationData`나 사용자가 선택한 경로에 저장하는 편이 안전하다.

## Deserialize and Validate

```csharp
string json = await File.ReadAllTextAsync(path);
UserProfile? profile = JsonConvert.DeserializeObject<UserProfile>(json);

if (profile is null || string.IsNullOrWhiteSpace(profile.Name))
{
    throw new InvalidDataException("User profile is missing required data.");
}
```

역직렬화가 성공해도 값이 업무 규칙에 맞는지는 별도로 검사해야 한다. 외부 입력에는 예외 처리와 크기 제한도 필요하다.

> 신뢰할 수 없는 JSON에 `TypeNameHandling.Auto` 또는 `All`을 무심코 사용하면 임의 타입 생성으로 이어질 수 있다. 꼭 필요하지 않다면 기본값 `None`을 유지한다.

## Deployment

- **.NET Framework**: EXE와 `Newtonsoft.Json.dll` 등 출력 폴더의 의존 파일을 함께 배포한다.
- **Modern .NET**: Visual Studio Publish 또는 `dotnet publish`를 사용한다.
- **Single-file publish**: 최신 .NET에서는 런타임과 의존성을 하나의 배포 파일로 묶을 수 있다.

```powershell
dotnet publish -c Release -r win-x64 -p:PublishSingleFile=true --self-contained true
```

과거의 `AppDomain.AssemblyResolve` 방식은 .NET Framework에서 가능하지만 리소스 충돌과 로드 컨텍스트를 직접 처리해야 한다. 새 프로젝트에서는 공식 publish 기능을 우선한다.

## Checklist

- 모델 속성과 JSON 필드 이름 규칙을 정했는가?
- null, 누락 필드, 잘못된 타입을 검증하는가?
- 실행 폴더 대신 적절한 사용자 데이터 경로를 사용하는가?
- EXE만 복사하지 않고 publish 결과를 배포하는가?
- 민감한 데이터가 JSON이나 로그에 노출되지 않는가?
