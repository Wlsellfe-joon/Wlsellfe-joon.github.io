## Virtual Dispatch

기반 클래스 포인터나 참조가 파생 객체를 가리킬 때 비가상 함수는 표현식의 정적 타입을, 가상 함수는 실제 객체의 동적 타입을 기준으로 호출된다.

```cpp
#include <iostream>

class Animal
{
public:
    void cry() const { std::cout << "Animal crying\n"; }

    virtual void laugh() const
    {
        std::cout << "Animal laughing\n";
    }

    virtual ~Animal() = default;
};

class Dog final : public Animal
{
public:
    void cry() const { std::cout << "Dog crying\n"; }

    void laugh() const override
    {
        std::cout << "Dog laughing\n";
    }
};

int main()
{
    Dog dog;
    Animal* animal = &dog;

    animal->cry();   // Animal::cry
    animal->laugh(); // Dog::laugh
}
```

`override`는 기반 함수와 시그니처가 다르면 컴파일 오류를 발생시켜 오타나 `const` 누락을 잡아준다.

## Why the Destructor Is Virtual

가상 함수가 있는 타입을 기반 클래스 포인터로 소유하고 삭제할 수 있다면 소멸자도 public virtual이어야 한다.

```cpp
std::unique_ptr<Animal> animal = std::make_unique<Dog>();
// 범위를 벗어나면 Dog와 Animal 소멸자가 올바른 순서로 호출된다.
```

기반 소멸자가 virtual이 아닌 상태에서 기반 포인터로 파생 객체를 삭제하면 올바른 파생 소멸이 보장되지 않는다. 일반적인 소유 관계에서는 raw `new`/`delete`보다 `std::unique_ptr`을 우선한다.

## Protected Constructor

protected 생성자는 외부 코드가 기반 타입을 직접 만들지 못하게 하면서 파생 타입의 생성은 허용한다.

```cpp
class Animal
{
protected:
    Animal() = default;

public:
    virtual ~Animal() = default;
};

class Dog final : public Animal
{
public:
    Dog() = default;
};

int main()
{
    // Animal animal; // 컴파일 오류
    Dog dog;          // 정상
}
```

“개념적으로 직접 생성할 수 없는 타입”이라는 의도라면 순수 가상 함수를 둔 추상 클래스로 표현하는 편이 더 명확할 수 있다.

```cpp
class Animal
{
public:
    virtual void speak() const = 0;
    virtual ~Animal() = default;
};
```

## Protected Destructor

protected 소멸자는 객체를 자동으로 힙에 생성하지 않는다. 저장 위치는 선언 방식이 결정한다. 이 접근 지정자는 외부 코드가 객체를 직접 파괴하지 못하게 하므로 함수 범위의 지역 객체 생성과 외부 `delete`가 제한된다.

```cpp
class Interface
{
public:
    virtual void run() = 0;

protected:
    ~Interface() = default;
};
```

다형 기반 타입의 소멸자는 보통 다음 둘 중 하나다.

- 기반 포인터로 삭제할 수 있다면 **public virtual**
- 기반 인터페이스를 통한 삭제를 막는다면 **protected non-virtual**

`delete this`는 일반적인 해결책이 아니다. 객체가 반드시 동적 할당되었다는 보장과 호출 이후 접근 금지, 중복 삭제 방지 등 강한 규칙이 필요하다. 소유권은 스마트 포인터나 명시적인 factory/API로 표현하는 편이 안전하다.

## Takeaways

- 다형 동작에는 기반 함수의 `virtual`과 파생 함수의 `override`를 함께 사용한다.
- 기반 포인터로 삭제할 타입은 public virtual destructor를 갖게 한다.
- protected constructor는 직접 생성을 제한하지만 추상 타입과 같은 의미는 아니다.
- protected destructor는 저장 위치가 아니라 파괴 권한을 제어한다.
- 수동 메모리 관리보다 RAII와 스마트 포인터를 우선한다.
